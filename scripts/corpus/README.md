# scripts/corpus/

Local, **opt-in** tooling for probing external KiCad corpora with this repo's own
parsers. Nothing here is part of the installed `kct` package, nothing here runs in
CI, and nothing under `tests/` imports it — these scripts do network I/O and are
run by hand.

## `probe_open_schematics.py`

Samples N random records from the Hugging Face dataset
[`bshada/open-schematics`](https://huggingface.co/datasets/bshada/open-schematics)
(87,931 records / ~317 GB, CC-BY-4.0), parses each payload with
`kicad_tools.schema.Schematic.load` / `kicad_tools.schema.PCB.load`, and writes a
**failure-taxonomy report** — JSON for machine consumption plus a human-readable
summary.

Why: every parser measurement in this repo today runs against the 9 in-repo
boards, all of them generated by `kct` itself. The corpus is ~75k real
`.kicad_sch` + paired `.kicad_pcb` files written by other people and other KiCad
versions — a free regression/fuzzing corpus for parser hardening (#4830).

### Invocation

```bash
# 50 random records (the default); reports land in scripts/corpus/.cache/
uv run python scripts/corpus/probe_open_schematics.py

# small, reproducible sample — the same --seed re-samples the same records
uv run python scripts/corpus/probe_open_schematics.py --n 10 --seed 1234

# offline: exercise the same parse/classify/report path on in-repo KiCad files
uv run python scripts/corpus/probe_open_schematics.py --dry-run --n 20 --seed 7

# schematics only, keep every sampled payload for triage
uv run python scripts/corpus/probe_open_schematics.py --kinds schematic --keep-sources all
```

`--help` lists the full flag set (`--n`, `--seed`, `--out`, `--dataset`,
`--config`, `--split`, `--kinds`, `--max-bytes`, `--timeout`, `--retries`,
`--keep-sources`, `--dry-run`, `--quiet`).

A run takes roughly 5 s per record (each record is a schematic plus every PCB
file of the same design, often several MB of JSON), so the default `--n 50` is a
~4 minute coffee break.

### Where the bytes go

| What | Where | Committed? |
|------|-------|------------|
| Sampled payloads while parsing | a `kct-corpus-probe-*` scratch dir under the system temp dir, deleted on exit | never |
| Reports (`probe-<UTC stamp>.json` / `.txt`) | `scripts/corpus/.cache/` (gitignored) | never |
| Retained payloads (`--keep-sources`) | `scripts/corpus/.cache/sources/` (gitignored) | never |

`git status` is clean after a run. Point `--out` somewhere outside the repo if
you prefer; nothing else writes into the working tree.

### Dependencies

stdlib + `requests` only (already available via the `dev` and `parts` extras).
The Hugging Face `datasets` library is deliberately **not** used and must not be
added as a default dependency — the script talks to the plain HTTP endpoints:

- `https://huggingface.co/api/datasets/<id>` — dataset commit sha, so a report
  pins the exact revision it sampled.
- `https://datasets-server.huggingface.co/info` — row count (the sampling
  universe).
- `https://datasets-server.huggingface.co/rows?...&offset=<n>&length=1` — one
  record, with the raw `.kicad_sch` / `.kicad_pcb` sources inline as strings.

The dataset is published as ~1,700 parquet shards, *not* as individual files, so
listing the repo tree (`/api/datasets/<id>/tree/main`) gives no per-record
granularity and the smallest shard is still hundreds of MB. The datasets-server
row API is what makes "download only the N records we sampled" possible.

### Reading the report

Outcomes are bucketed so each class maps to a different engineering action:

| Class | Meaning |
|-------|---------|
| `ok` | parsed cleanly |
| `sexpr-syntax-error` | the tokenizer/grammar rejected the file |
| `wrong-root-token` | parsed, but the root tag was not `kicad_sch`/`kicad_pcb` |
| `encoding-error` | not decodable as UTF-8 |
| `missing-node-or-atom` | `KeyError`/`IndexError` walking the tree after parsing |
| `unexpected-value` | `ValueError`/`TypeError` converting an atom |
| `unexpected-tree-shape` | `AttributeError` on an unexpected node |
| `recursion-limit`, `out-of-memory` | resource limits hit while parsing |
| `kicad-tools-error` | any other `KiCadToolsError` subclass |
| `uncaught-internal-error` | anything else — triage individually |
| `skipped-non-kicad-format` | legacy Eeschema / Altium / non-KiCad payload (no parser exists; not a defect) |
| `skipped-empty-payload`, `skipped-oversize-payload` | nothing to parse / above `--max-bytes` |
| `skipped-dataset-truncated-cell` | the dataset API elided part of the row; parsing it would fake a syntax error |
| `network-error` | the record could not be fetched after retries |

Only the first ten count toward `parse_failure_rate`. The report also cross-tabs
outcomes against the declared KiCad file-format version (`(version 20231120)`),
which is how "we break on files older/newer than X" would show up — this repo
has no version-reject path today.

Failure messages are grouped by a digit-normalised signature, so
`Expected atom at position 4172` and `... at position 91` count as one offender.
