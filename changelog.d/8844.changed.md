- **`fab_dfm_parity` marks `silkscreen_to_hole` as `partial`** (Issue #8844). The
  JLCDFM parity table (now v3) credits the new `silk_hole_overlap` rule, which
  retires the last `not_covered` danger-capable category: `kct check --mfr jlcpcb`
  no longer returns the `incomplete` verdict (exit 2) on an otherwise clean board
  for want of a silk-to-hole rule. Still `partial`, not `covered` — the rule
  tests overlap at 0 mm, so a sub-clearance gap that does not touch the drill is
  unchecked, and text is tested as its bounding box.
- **`fab_dfm_parity` states why `silkscreen_line_width` is `partial`** (Issue #8844).
  The row (parity table now v4) no longer says kct has "only a text-thickness
  floor": `silkscreen_line_width` checks every silk graphic primitive and
  `silkscreen_text_thickness` checks text, both against JLCPCB's published
  >= 0.15 mm. The residual gap is on the fab tool's side: JLCDFM's 63
  line-width warnings on the epic #8838 board came from gerbers with no silk
  stroke below 0.150 mm, so JLCDFM flags silk that meets the published floor.
  How it selects the items it flags is unknown (follow-up #8943).
