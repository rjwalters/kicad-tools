- **`kct route --differential-pairs` can spend longer on pairs it cannot
  couple** (Issue #6835). Without `--diffpair-per-pair-timeout`, the coupled
  search's only bound is its iteration budget, which is now 700,000 per pair
  instead of 40,000. A pair that fails both phases can now take about 7-8 s
  instead of about 0.5 s (measured: Board07 DQS 7.5 s, 06rf USB3_TX2 7.6 s).
  Set `KCT_COUPLED_FLAGOFF_MAX_ITERS=40000` to restore the old cap, or pass
  `--diffpair-per-pair-timeout` to bound each pair by wall clock.
