- **`kct export` and `kct readiness --generate` may modify the board in place** (Issue #9799). Both now run the default silk-legalisation pass on the board being exported — before preflight, plotting and hashing — and the pass edits it in place when it fixes anything (an already-legal board is not re-saved). If you export an authored board with illegal silk and want it preserved exactly, pass `--no-silk-fix`; the same flag exists on `kct route`, `kct route-auto` and `kct optimize-placement`, where it also bypasses the placement snap's reference re-anchoring (`repair_snapped_silk_refs`). What the pass cannot fix is named in the output and stays a `kct check` finding — no allowance or tolerance is added anywhere.
