- **`kct route` no longer demotes boundary-exact nets demoted by C++ float32 coordinate noise** (Issue #9734). The C++ backend's `Segment`/`Via` structs store float32 coordinates, whose ulp at board scale (~1.5e-5 mm at 130 mm) round-tripped grid-exact values like `132.855` as `132.854996`; pairs designed to sit exactly at the DRC clearance boundary `(w_a + w_b) / 2 + trace_clearance` landed a few nanometres short, and the finalize segment-vs-segment SHORT gate correctly refused to ship them -- on board 05 this demoted `VCP` to unrouted (route exit 3, 36/37 nets) and the chained completion pass declined it `no-path`. Every C++-emitted segment and via coordinate is now snapped back onto the 4-decimal (0.1 um) lattice at the backend boundary, the same contract `RoutingGrid.grid_to_world` already applies to Python-backend geometry, so both backends emit identical, lattice-exact copper. Board 05's unattended route is green again on seeds 42/7/1337 (`kct route` exit 0, 37/37 nets, 0 DRC errors/warnings/unconnected, copper + label LVS clean on the pinned toolchain).
