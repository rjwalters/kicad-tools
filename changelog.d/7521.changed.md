- **`kct check` leaves KiCad tuning patterns out of the diff-pair
  uncoupled length, as kicad-cli 10.0.6 does** (Issue #7521, operator ruling
  Q16). `diffpair_uncoupled_length` drops tracks owned by a
  `(generated ... (type tuning_pattern))` object on both sides of the pair.
  The partner's copper opposite a skew bump therefore still counts, and the
  finding names how much pattern copper it excluded. The router's
  skew-tuner uncoupled guard uses the same measure. If the pattern form of a
  bump would push the pair over its limit, the tuner tries the same bump as
  plain copper (the earlier output) before giving up. On boards with
  patterns, kct and pinned kicad-cli now report the same figure. Boards
  without patterns are measured as before.
