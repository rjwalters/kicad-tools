- **`kct route --complete` no longer refuses links on pads that already have copper or sit beside a high-clearance sibling pad** (Issue #9636). A link whose pad already carries a (narrower) track of the net now starts from that kept copper instead of re-escaping the pin at class width; the other pad of the same footprint no longer walls a pad in through its class keep-out (copper is held to the gap the part itself leaves); `kct net-status` / the stuck classifier no longer calls a two-pad part's own other pad a "committed strict copper" blocker; and a refusal for trace width names the width tried and the widest trace that would leave the pad.
