- **`kct route --backend cpp` emits the same taper copper as the Python backend** (Issue #9851). The native result adapter tapered each per-cell segment independently while the Python converter tapered each merged straight run once, so identical A* paths emitted different `#1018` cut positions, piece counts and widths near every fine-pitch pad (43 vs 57 pieces on the reproduction fixture). The adapter now regroups its per-cell segments into the same straight runs before tapering through the shared `neck_down` pipeline, and the Python converter's end-pad tail extends the open run (tapered once over the whole run) instead of re-tapering from the last cut point, so both backends emit identical segment bytes for the same path.
