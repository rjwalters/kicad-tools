- **`kct readiness --generate` no longer cuts doubled power copper its own check gate requires** (Issue #9747). The cleanup's prune step now loads the same current-paths sidecar (explicit `--current-paths` in `check_args`, else auto-discovered beside the board) that the `kct_check` gate loads, so a bar that would drop below its declared current's IPC-2221 width on any layer is kept -- a 2-layer board carrying a pulsed path as the same wide bar on both outer layers no longer fails tapeout with `path_ampacity` errors the cleanup itself introduced. When a pre/post-cleanup comparison confirms the cleanup introduced a blocking `kct_check` finding, the blocker now names `copper_cleanup` and suggests `--skip-cleanup` instead of pointing at the committed board. A malformed sidecar is recorded as a failed prune step rather than pruning without declarations.
