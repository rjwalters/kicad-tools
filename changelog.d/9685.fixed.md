- **`kct route --voltage-map` audits committed copper against the board edge** (Issue #9685). The post-route HV pairwise gate had no copper-vs-`Edge.Cuts` model at all, so `route --complete --voltage-map` could commit a track closer to the board edge than the map's creepage table requires and still exit 0 with a SUCCESS banner, while `kct creepage` failed the same board's `net vs <board edge>` rows (the reporter's board: a gate track 1.50 mm from the edge against a 2.0 mm requirement). The audit now scores one copper-vs-board-edge row per HV net at the same requirement the census computes -- worst-case interval differencing against the map's `_edge_voltage` reference (default 0 V), the same standard lookup, no `_pair_bounds` -- so the `--complete` per-link rollback and the final exit-code gate both see edge shortfalls: the link is rolled back and reported (`creepage-rolled-back`, blocking net `<board edge>`) or the run exits non-zero. The `--complete-report` JSON gains a `creepage_gate` object (`committed_links_verified`, `rolled_back`, `checks`) and the run summary states how many committed links the voltage-map gate verified.
