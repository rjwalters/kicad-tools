- **`kct route` takes an advisory run lock on its output** (Issue #9628). Two
  overlapping `kct route` runs on one `--output` no longer silently delete each
  other's copper: the run holds `.<output name>.kct-route.lock` beside the
  output (pid, host, start time), released on exit, error, Ctrl-C/SIGTERM and
  `--timeout` expiry. A lock whose pid is dead on this host is stolen; one from
  another host or that cannot be parsed is refused, never stolen.
  `KCT_ROUTE_LOCK_POLICY=error|warn|ignore` (default `error`) controls it.
