- **Board recipe loaders no longer let one board's siblings shadow another's in-process** (Issue #9351). `load_board_recipe_module` in `scripts/ci/net_class_map_resolver.py` and `scripts/ci/check_matchgroup_coverage.py` namespaced only the top recipe module, so the recipes' bare `import generate_pcb` / `import generate_schematic` cached under shared `sys.modules` keys and the first board loaded in a process won them — a later board's recipe silently audited against the wrong board's declarations. Both loaders now evict stale sibling entries before the import and restore `sys.modules` afterwards, symmetric with their existing `sys.path` restore.
