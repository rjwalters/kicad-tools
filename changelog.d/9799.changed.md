- **Silk is legal by default across the pipeline** (Issue #9799, #9795 phase 3). `kct route`, `kct route-auto`, `kct optimize-placement`, `kct export` and `kct readiness --generate` now run the shared silk-legalisation pass (`legalize_silk`, #9797) on the board they publish — after copper is written and before any check judges silk — so a normal route, placement or export can no longer ship an authored silk defect. The command output (and the `silk_fix` key of the `--format json` documents) names every edit and each item the pass could not fix; unresolved items stay `kct check` findings (nothing is waived, and vias are never clipped, moved or reported). An already-legal board is not re-saved, so route → export changes nothing the second time. Pass `--no-silk-fix` to any of these commands to leave authored silk byte-identical.
