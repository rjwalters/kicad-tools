- **`kct create-pcb` no longer repeats library child uuids across placed footprints** (Issue #9485). `PCB.add_footprint_from_file` now mints a fresh, deterministic uuid for every `uuid`/`tstamp` node in a placed footprint (graphic children and properties, not just pads), so boards with several `SOT-89-3`, `TestPoint_THTPad` or `D_SOD-123` parts no longer trip `mask_to_copper`'s duplicate-UUID refusal in `kct check`. The same placement now also keeps `(group ...)` membership intact: the `(members ...)` lists of group-bearing library footprints (such as the `Panelization` `*_Trace` mousebites) follow the re-minted pad uuids, so KiCad no longer silently discards those groups when it loads the board.
