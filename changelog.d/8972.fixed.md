- **`kct check` fab-DFM parity attributes trace-band `physical_copper_gap` findings to `trace_spacing`** (Issue #8972). The pass graded same-net trace gaps against the fab's trace band but the parity table's flat rule-id key filed every `physical_copper_gap` finding under `pad_spacing`, so `trace_spacing` could read `kct 0 err` beside the fab's recorded danger (spurious `** fab danger, kct 0 errors **` mark) while `pad_spacing`'s count was inflated. Findings now carry the band they were graded against (`fab_band`: `trace` / `pad`), the table attributes `rule_id#band` keys per row, and the table version is 7. The rule id is unchanged, so existing `.kct_waivers.json` entries keep matching.
