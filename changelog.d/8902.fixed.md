- **Fab DFM parity table no longer claims "no rule" for rules that shipped**
  (Issue #8902). The `kct check --mfr jlcpcb` parity stanza described `main` as
  of PR #8855 and had gone stale: `tht_to_smd`, `negative_soldermask_expansion`
  and `soldermask_opening_multiple_segments` said "no rule" after
  `tht_smd_spacing`, `mask_negative_expansion` and `mask_multi_segment` shipped,
  and the `trace_spacing` / `pad_spacing` / `solder_mask_opening_exposing_trace`
  notes still described coverage gaps that PRs #8849 and #8852 closed. Every row
  now names its rule id(s) and says what is still unchecked (table version 2).
  Because `tht_to_smd` is no longer `not_covered`, it stops contributing to the
  `incomplete` verdict on its own; `kct check --mfr jlcpcb` still reports
  `incomplete` while `silkscreen_to_hole` has no rule. A new test fails if a
  rule is registered while its row still claims no rule.
