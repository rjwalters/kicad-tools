- **`kct check` no longer prints `Overall: PASSED` above a `BLOCKING UNKNOWN`
  row and exit 2** (Issue #8949). When a blocking category could not complete
  its assessment — a default-applied `mask_to_copper` coverage check, a
  stackup with no DFM-table entry, a danger-capable fab DFM parity row — the
  incompleteness now reaches the meta rollup through one flag
  (`MetaCheckResult.coverage_incomplete`, consulted by `compute_overall`),
  so the printed `Overall:` line, `meta_checks.overall` in the JSON report
  and the exit code all read one source: the line reads
  `Overall:   INCOMPLETE (mask_to_copper)` and exit 2, or exit 0 under
  `--allow-incomplete` with the line still honest. A FAILED board still
  reads `FAILED`. The human-readable `Mask-to-copper:` stanza now collapses
  repeated reason lines with the same shared de-dup/truncate rule the
  coverage row uses (`collapse_reasons`, stdout bound 8 distinct reasons,
  `(+N more)` for the remainder — every distinct cause up to the bound stays
  visible), and an incomplete assessment prints one remediation line naming
  what to configure (`KCT_KICAD_DOCKER=1` / a qualified kicad-cli). The
  remediation hint is deliberately not serialized: the JSON report's schema
  is unchanged, machine consumers keep reading `verdict` and `exit_code`.
