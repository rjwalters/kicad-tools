- **`kct check --format json` names the categories that did not complete this
  run** (Issue #9062). New additive key `meta_checks.incomplete_categories`
  (list of strings) lists every tracked category (`mask_to_copper`,
  `dfm_table`, `fab_dfm_parity`) whose check did not finish, agreeing with
  `coverage.*.state`. It is wider than the #8949 incompleteness that drives
  an `INCOMPLETE` verdict: a default-applied `mask_to_copper` assessment that
  did not pass *with* provisional `violation`/`uncertain` measurements still
  fails the board, and its category is now named in the list while the verdict
  stays `fail` — previously the list a consumer would read for "which
  categories got no result" was `fab_dfm_parity.incomplete_categories`, which
  is static table data and never reflected the run. That parity-table key is
  unchanged; its docstring and the CLI reference now say it is table-only and
  point at `meta_checks.incomplete_categories` for run-time state. Verdict and
  exit code are unchanged (`FAILED` still ranks before `INCOMPLETE`;
  `--drc-only` reports omit `meta_checks` entirely, so the key is absent there
  as before).
