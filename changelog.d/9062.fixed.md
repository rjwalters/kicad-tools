- **`kct check --format json` names the categories that did not complete this
  run** (Issue #9062). New additive key `meta_checks.incomplete_categories`
  (list of strings) lists every default-applied tracked category
  (`mask_to_copper`, `dfm_table`, `fab_dfm_parity`) whose check did not
  finish, agreeing with `coverage.*.state`, except that an explicitly
  requested mask check that cannot run is FAILED (its
  `coverage.mask_to_copper` state reads `unknown`) and is not named (#8949).
  It is wider than the #8949 incompleteness that drives
  an `INCOMPLETE` verdict: a default-applied `mask_to_copper` assessment that
  did not complete is named even when its provisional `violation`/`uncertain`
  measurements keep the verdict `fail`. A mask check that *completed* and
  found a real violation is not named (its `coverage.*.state` reads `checked`)
  — the list is keyed on `assessment.coverage`, never `assessment.passed`.
  Previously the list a consumer would read for "which
  categories got no result" was `fab_dfm_parity.incomplete_categories`, which
  is static table data and never reflected the run. That parity-table key is
  unchanged; its docstring and the CLI reference now say it is table-only and
  point at `meta_checks.incomplete_categories` for run-time state. Verdict and
  exit code are unchanged (`FAILED` still ranks before `INCOMPLETE`;
  `--drc-only` reports omit `meta_checks` entirely, so the key is absent there
  as before).
