- **Grid router keeps own-net legs and the neck-down taper out of the fab pad-spacing slit band** (Issue #9019). With the stackup's `pad_spacing` detection edge resolved, the Python and C++ grid A* refuse a step whose copper parks in `(0, edge)` beside an own-net SMD pad (union with the pad or clear of the edge, the #9012 two-region rule), and the #1018 taper no longer narrows a leg into that band. Pads the leg is unioned with through the path (its own start/end pads) are exempt, so a plain pad-to-pad connection stays planar and via-free instead of escaping through a pair of pad-edge vias. The gate is a preference, not a hard rule: a net whose gated search finds no path is retried once with the gate off — only when the gate actually refused a step of that search, with the fallback counted and logged — so it never costs a connection. The native extension `BUILD_VERSION` is now 72 (`uv run kct build-native`). Board 02's seed-42 route is unchanged from the pre-gate baseline (12/12 nets, 29 vias, no `physical_copper_gap` findings); board 06's seed-42 route copper is identical to the baseline — its remaining slits belong to the coupled-pair engine, held separately by #9140.
