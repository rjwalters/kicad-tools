- **`mask_to_copper` completes on boards with keepout rule areas** (Issue #9234).
  A keepout rule area embedded in a footprint (the stock RF-module footprint
  shape) plots no copper and has no mask presence, but was still treated as a
  required native object the per-object worker never found, so
  `coverage.mask_to_copper` read `unknown` for the whole board and every
  `mask_to_copper` finding was provisional. Rule areas — footprint-embedded or
  at board level — are no longer inventoried native objects and no longer
  report as `uninventoried native ZONE`; real (filled) zones are unchanged.
  When an object does still block completion, the reason now names its type
  and parent (`<uuid>: missing/ambiguous native object (zone in footprint
  U1)`) instead of only a uuid. And `fab_dfm_parity.incomplete_categories`
  now also names `solder_mask_opening_exposing_trace` whenever a
  default-applied mask-to-copper assessment did not complete (previously
  static table data only, #9062), so the fab's solder-mask category cannot be
  compared on such a run; `meta_checks.incomplete_categories`, the verdict
  and the exit code are unchanged.
