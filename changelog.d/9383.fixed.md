- **CI no longer strands a cancelled `Changelog Fragment Check` row on a PR
  head** (Issue #9383). Two quick `pull_request` events on one head (a PR
  created and immediately edited, a push plus a label flip) raced in the
  workflow's shared `changelog-<PR>` concurrency group and the cancelled
  first run stayed a permanent red row that exact-head CI gates read as
  failed even after the newer run succeeded. Every event now gets its own
  per-run group, so no run of the check can be cancelled by another.
