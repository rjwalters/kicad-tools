- **`kct readiness` collects project inputs from outside the PCB directory**
  (Issue #5813). A schematic kept in a sibling `schematics/` tree (passed with
  `--sch`) and a custom symbol/footprint library reached through a
  parent-relative library-table entry (`(uri "${KIPRJMOD}/../symbols/lib.kicad_sym")`)
  are now collected into the package under `<pcb-dir>/kct-collected/` instead of
  failing the run with `'...kicad_sch' is not in the subpath of '...'` or
  `Project dependency is outside the package root: ...`. Collected files are
  hashed into `inputs` exactly like in-directory inputs, recorded with their
  origin in a new additive `collected_dependencies` block in
  `output/readiness.json`, and stored in `kicad_project.zip` with that archive's
  library tables rewritten to name them -- so the exported project opens without
  the surrounding checkout. The checkout's own tables are never rewritten, and
  `kct-collected/` is rebuilt from the current sources on every run, so an edit
  to a shared library is still picked up by the next run. Collection is bounded
  by a **project root** -- the board directory, widened to the nearest common
  ancestor of the paths you name (at most two levels up), or declared with the
  new `--project-root DIR`. Nothing outside that root is collected: missing
  files, undeclared dependencies, `../../` and symlink escapes, an out-of-root
  `--project-root`, and a collected sheet that references a file back inside the
  PCB directory are all refused before anything is written (exit 2, with the
  supported layout named in the message). See `docs/reference/cli.md` ->
  `readiness` -> "Project layouts".
