- **`kct check` prints kct-vs-fab counts in the Fab DFM parity stanza** (Issue #8940). New `--fab-dfm-result PATH` accepts a recorded fab DFM tool result (JSON in the shape of `tests/fixtures/fab_dfm_parity/jlcdfm_*.json`, with a `counts` object). Given one, each `Fab DFM parity` row — and the `fab_dfm_parity` section of `--format json` — prints kct's own error/warning counts beside the fab's recorded danger/warning counts, visibly marks categories where the fab reports danger but kct reports zero errors, and renders rows kct cannot measure as `n/a (not measured)` instead of a misleading 0. Counts are attributed per category by an explicit rule-id key on the parity table (a tested partition, so no finding counts toward two categories) using the same `is_error`/`is_warning` predicates as the headline totals. Without the flag the stanza and JSON are unchanged; a malformed or unreadable result is a clear error, never a silent fall back.
