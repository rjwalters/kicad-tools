- **`kct route --report-detour-ratio` / `--detour-repair` no longer spend the real run's `--timeout` budget** (Issue #9244). The alone-on-empty probe pre-pass measures its own wall-clock cost and that cost is now excluded from the routing stage timeout, the CLI routing/wall-clock deadlines (`--timeout`, `--auto-fix` reserves, per-tier budget slices) and installed excursion deadlines, so a binding time limit can no longer change which real searches time out and therefore the routed copper. Residual: the hard supervisor cap (`KCT_ROUTE_INVOCATION_DEADLINE`) still bounds the whole invocation, so under a binding hard cap the flag can still change the output exactly as a slower machine would.
