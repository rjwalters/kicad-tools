- **`coverage.mask_to_copper` no longer reports `checked` for an assessment that
  could not evaluate the board** (Issue #8924). `check_mask_to_copper` built its
  `MaskCopperAssessment` as a local, so `kct check`'s coverage loop never saw it
  and the row fell through to the unconditional `checked` default: a
  `--mfr jlcpcb` run on board 00 reported
  `coverage.mask_to_copper.status = "checked"` while the same report's
  `mask_copper_assessments[0].coverage` was `"incomplete"` with 19 reasons, and
  `summary.coverage_blocking_unknown` was `[]`. The row now follows the
  assessment's own `coverage`: `complete` stays `checked`, while `incomplete`
  and `not_run` report `unknown:assessment <state> (<reasons>)` — de-duplicated
  and truncated, since the live case repeats one reason 13 times. The row keys
  on `coverage`, never on `passed`, so a board whose mask check ran fine and
  found real violations is still `checked` with error findings.
