- **`tht_smd_spacing` judges wire-anchor vias, and a `mask_to_copper` run that could not execute now says so** (Issue #8914). JLCDFM reported five danger-level THT-to-SMD items on a consumer board where `kct check --mfr jlcpcb` reported one; the three it missed outright were 1.3-1.42 mm-drill wire-anchor **vias**, which the rule never looked at because the only way to include vias was an `include_vias=True` argument no `kct check` code path ever passed. The rule now classes a plated hole the way the fab does -- by drill diameter -- and judges any via drilled 1.0 mm or more exactly like a through-hole component pad, while fan-out vias stay unjudged (on this repo's routed boards, where every via drills 0.15-0.3 mm, finding counts are unchanged; judging every via would add 176-1,068 findings per board). A THT or SMD pad whose `shape` the rule cannot reproduce (`custom`, `trapezoid`) now reports `tht_smd_spacing_incomplete` at *info* instead of being dropped silently. Separately, a `mask_to_copper` assessment that ends `incomplete` or `not_run` now emits a `mask_to_copper_incomplete` *info* finding carrying the reason, so a rule-by-rule comparison against the fab can no longer read "0 findings" for a check that never ran.
