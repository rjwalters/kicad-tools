- **`kct readiness` can newly report NOT_READY when a swapped footprint cannot
  be resolved** (Issue #8942). A replacement footprint the removed-pad scan
  still cannot find after project-table lookup is now reported as blocking
  `unknown` coverage (`removed_pad_scan`) in the `kct check` report, so
  sign-off refuses instead of certifying a scan it silently skipped;
  `kct check`'s own exit code is unchanged. Boards with no resolvable
  schematic or no footprint swaps stay `skipped` and never block.
