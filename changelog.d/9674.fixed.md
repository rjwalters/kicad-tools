- **`kct apply --checked` no longer reports items that dedupe skipped** (Issue #9674). An item whose dedupe key is already on the board is skipped by `add_trace`/`add_via` dedupe (a segment's key is net, layer, unordered endpoints and width; a via's is net, position and layers); the JSON report now carries `items_written` / `items_skipped_as_duplicate` and the text line says how many were skipped, so an all-duplicate batch reports `wrote 0 item(s)` instead of claiming a write that did not happen. A via's size and drill are outside its key, so a skipped via conflicts when none of the vias sharing its key matches both requested dimensions: it is not written, is counted under `items_skipped_conflicting`, and the text output names the existing and requested size/drill — an upsize request can no longer read as success. Arcs have no dedupe path and are appended on every successful apply. Docs for `kct probe` and the `probe_items` / `apply_items_checked` MCP tools now list the full 13-category check set, including the net-agnostic `physical_copper_gap` / `copper_sliver` fab passes (a same-net parallel track can fail the gap pass) and `tht_smd_spacing`.
