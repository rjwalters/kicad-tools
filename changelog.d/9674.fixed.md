- **`kct apply --checked` no longer reports items that dedupe skipped** (Issue #9674). An item whose exact copper is already on the board is skipped by `add_trace`/`add_via` dedupe; the JSON report now carries `items_written` / `items_skipped_as_duplicate` and the text line says how many were skipped, so an all-duplicate batch reports `wrote 0 item(s)` instead of claiming a write that did not happen. Docs for `kct probe` and the `probe_items` / `apply_items_checked` MCP tools now list the full 13-category check set, including the net-agnostic `physical_copper_gap` / `copper_sliver` fab passes (a same-net parallel track can fail the gap pass) and `tht_smd_spacing`.
