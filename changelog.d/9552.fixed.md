- **`kct check --migrate-waivers` says `[rule not evaluated in this run]` for every `needs_input` coverage state** (Issue #9552). An orphan whose rule reports `unknown` with a `needs_input:<X>` reason (`ampacity` when `project.kct` declares currents no net class maps, `sch_fields` without a schematic, a diff-pair rule without a net-class map, ...) now says "not evaluated" instead of implying its key changed -- the absent input keeps the rule from emitting anything, so the old generic wording was wrong for exactly these states. `unknown` reasons that evaluated the board partially (`zone_fills_absent`, `no_courtyard_geometry`, ...) keep the generic wording, and no waiver file content changes either way.
