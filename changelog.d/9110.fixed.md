- **`coupled_capture.replay()` no longer leaks ~140 MB of native memory per
  call** (Issue #9110). The nested `resolve` closure referenced itself, so
  every replay left a self-referencing cycle that pinned the object table --
  and with it every native `Grid3D`/`CoupledPathfinder` and route result --
  until the cyclic GC ran; resolution is now a module-level `_resolve`
  helper, so plain refcounting frees everything when a replay returns or
  raises.
