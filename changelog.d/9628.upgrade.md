- **A second concurrent `kct route` on the same output now refuses** (Issue #9628).
  It exits 1 before touching the output and names the holder and the lock file
  (`.<output name>.kct-route.lock`). Delete that file if you are sure no run is
  using the output, or set `KCT_ROUTE_LOCK_POLICY=warn` / `ignore` to bypass.
