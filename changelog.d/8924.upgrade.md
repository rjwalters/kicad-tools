- **`kct readiness` and `/kct:tapeout` can newly refuse a jlcpcb-tier board**
  (Issue #8924). `mask_to_copper` is a blocking category, so its new
  `unknown` row reaches `summary.coverage_blocking_unknown` and
  `kct readiness`'s `kct_check` gate returns `NOT_RUN` with a blocker — on any
  host whose native mask path cannot complete. Since #8842 an explicit
  `--mfr jlcpcb*` turns `mask_to_copper` on by default, so such a run that
  passed before this change now refuses sign-off. That is "unknown is not pass"
  (#5946) working as intended: zero mask findings from a check that never
  evaluated the board was never a pass. To clear it, supply a process policy
  with `--mask-copper-config`, deselect the category with
  `--skip mask_to_copper`, or complete the native path (a qualified KiCad plot
  profile — CI's pinned image reports `10.0.6`; a distro build reporting
  `10.0.6-10.0.6~ubuntu24.04.1` is not qualified). Do **not** work around it by
  removing `mask_to_copper` from `BLOCKING_CATEGORIES`; that silently weakens
  unrelated gates.
