- **`kct route` no longer reports phantom `routing short ... vs Net 0` findings on
  KiCad 10 name-only boards** (Issue #8658). Copper kept from the input board
  (`--preserve-existing`, `--complete`) was captured under net id 0 on boards that
  write `(net "NAME")` with no numeric ids, so a new trace joining its own net's
  kept trace failed the short check and the run exited non-zero on a board with no
  short. Kept copper now carries its real net, and a short between two different
  nets is still reported, under both nets' names. Side effect on these boards: a
  net that plain `--preserve-existing` re-routes now drops its stale kept copper,
  as numeric-dialect boards already did.
