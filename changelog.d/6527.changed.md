- **The Python routing fallback now runs the bidirectional A\* by default**
  (Issue #6527). Every fallback request without Steiner goals goes
  bidirectional first (`DesignRules.fallback_bidirectional_threshold = 0`)
  and retries one-way, sharing one deadline, if that fails. A bidirectional
  search now stops as soon as one frontier drains without meeting the
  other. Board 05's three failing requests used to take 100-120 s each and
  now take about 1 s; the routed copper is the same. On board 05 (#6508
  protocol) the board goes from 34/37 to 36/37 nets (the +5V/GND pours
  connect, unconnected 3 -> 1, 0 kicad-cli DRC errors) at about the same
  total route time. That gain comes from the different fallback copper,
  not from a better search.
