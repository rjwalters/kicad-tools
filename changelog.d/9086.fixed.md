- **`find_kicad_python` probes differently-named links to one interpreter** (Issue #9086). Candidate dedup used `Path.resolve()`, so under a `uv` venv — where `.venv/bin/python` symlinks to the system interpreter — `/usr/bin/python3` was skipped as already seen without ever being probed. With the venv python failing the `import pcbnew` probe, discovery returned `None` on exactly the apt-KiCad hosts where `/usr/bin/python3` has pcbnew, so `kct check --mfr jlcpcb` reported no pcbnew interpreter. Dedup now keys on the candidate path as listed (only exact repeated entries are skipped); a failing venv probe no longer hides the system interpreter it points to.
