- **`kct voltage-map-merge` merges per-scenario voltage maps into one envelope** (Issue #9582). A board whose nets take different potentials per operating scenario needed one `--voltage-map` per scenario, but every consumer takes only one — the workaround was hand-writing an envelope of ranges plus one `_pair_bounds` entry per varying-net pair. Author one map per scenario instead and merge: per-net `{min, max}` spans plus generated `_pair_bounds` entries that restore each pair's worst per-scenario |ΔV|. `_pair_bounds` now also accepts `max_dv: 0`, declaring a pair "always at the same potential". The envelope is for the interval-aware consumers (`kct creepage`, `kct audit`, `kct repair-creepage`, `kct route-link`); `kct route`/`kct pcb` collapse each net's range to one signed endpoint (#4411) and can understate a sign-flipping pair — the command warns on stderr when its output contains such pairs (and carries them in its `--format json` document), so drive route-time spacing with a per-scenario map and gate with the envelope.
